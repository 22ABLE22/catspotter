# Catspotter

从游戏截图中自动识别 n×n 彩色棋盘，并按游戏规则求出全部 n 只小猫的坐标。

提供两个版本，算法完全一致：

- **网页版（纯前端）**：打开网页 → 选图/拖图/粘贴 → 直接出答案。图片只在浏览器本地处理，不会上传。
- **命令行版（Python）**：`py-version/`，适合批量处理与二次开发。

## 关于游戏

本工具针对的是 **【数独爱消消】** 中的「找猫」玩法，同一玩法也以 **Meowdoku** 之名发行。
可通过以下渠道玩到：

- **Android / Google Play**：[Meowdoku: 脑力解谜游戏](https://play.google.com/store/apps/details?id=com.oakever.meowdoku)
- **哔哩哔哩移动端**：[数独爱消消](https://miniapp.bilibili.com/game/biligame8829fe8973b3e9e9)
- **微信小程序**：`#小程序://数独爱消消/7B5WEnLxAjgBKJj`

棋盘由 n×n 个纯色格子组成（共 n 种颜色，每种颜色连成一片），需要在其中找出 n 只小猫。
本工具的输入就是这类关卡的游戏截图，与具体平台无关——手机截图、模拟器截图都可以。

## 规则

1. 每种颜色恰好 1 只猫
2. 每行每列恰好 1 只猫
3. 任意两只猫不能相邻：**上下左右和对角线都不行（八邻）**
   —— 中间的格子周围 8 格都不能有猫，贴边的格子 5 格，贴角的格子 3 格

## 命令行版（Python）

```
cd py-version
pip install numpy pillow

python solver.py 截图.jpg                 # 打印小猫坐标
python solver.py 截图.jpg --mark          # 另存答案标注图, 自动命名为同名 .png
python solver.py 截图.jpg --mark out.png  # 另存到指定路径
python solver.py 截图.jpg --json          # JSON 输出(方便程序调用)
solve.bat 截图.jpg                        # Windows 下一键运行
```

`example/` 目录下提供 3 张示例截图，覆盖三种典型情况：

| 文件 | 棋盘 | 说明 |
| --- | --- | --- |
| `example01.jpg` | 16 × 16 | 原尺寸截图，走"格线法" |
| `example02.jpg` | 12 × 12 | 被缩小过的截图，格线被压糊，走"周期法"兜底 |
| `example03.jpg` | 6 × 6 | 带游戏预亮的一只猫（猫脸盖住格子颜色），走遮挡回填 |

```
python py-version/solver.py example/example01.jpg --mark
```

坐标系与游戏画面一致：`x` 为列（自左向右 1…n），`y` 为行（自下而上 1…n），左下角为 `(1,1)`。

`--mark` 不带参数时，会在截图所在目录生成同名 `.png`（例如 `1.jpg` → `1.png`）；
若输入的截图本身就是 `.png`，则生成 `xxx_marked.png`，不会覆盖原图。

示例输出：

```
棋盘: 16 x 16   (唯一解)
小猫坐标 (x=列, y=行):
  (1,8)  (2,11)  (3,15)  (4,5)  (5,10)  (6,6)  (7,4)  (8,2)
  (9,7)  (10,9)  (11,13)  (12,16)  (13,14)  (14,12)  (15,3)  (16,1)
```

## 实现流程

1. **定位棋盘**（两种策略，先试 A 不行再自动换 B）：
   - **A 格线法**：按饱和度取出所有"彩色"像素，统计每行/每列的彩色像素数，
     挑出等间距、等宽的连续条带，得到 n 与每一格的精确边界
     （对界面上的文字、图标、按钮等干扰免疫）。
   - **B 周期法**：截图被缩小、压缩后，格子之间那 2 像素的缝隙会被 JPEG 糊平，
     投影变成一条平线，A 就失效了。此时改用：
     1. 取**彩色像素的最大连通块**作为棋盘（先下采样成小块，块内有彩色就算彩色，
        再膨胀两格把格子缝连起来；最后只在块范围内用 25% 阈值求像素级边界）。
        这样既不会被浅色格子造成的低谷截断，也不会把远处的界面元素并进来；
     2. 对"每行/每列的平均亮度、平均饱和度"做**自相关**求出格子边长；
     3. 按 n 均匀切分。取自相关接近最强里**最小**的周期（基频），避免把 n 估成一半。
     外框同时保留"投影阈值法"作为第二个候选，两种外框 × 至多 4 个 n 一起交给求解循环试。
2. **多点采样投票**：每格取中心 + 四象限共 5 个小块，各自求中位数颜色，
   再用 ΔE 投票选出"共识色"。某个小块不小心压到圆角、描边或邻格时会被其余小块投票排除；
   共识度低的格子会在结果里给出提示。
3. **被遮挡格子的回填**（对应游戏"预亮一只猫"的关卡）：
   游戏会事先点亮一只猫，猫脸图标把那一格的颜色完全盖住，采样到的是图标色而非底色。
   直接聚类会把图标色当成新颜色，把某种颜色拆成两块，导致所有划分作废、整体报"无解"。
   处理方式：先把这些格子**摘出聚类**，聚完再回填——
   - 判据：共识度低，**或**采样色饱和度极低（图标是灰白黑色系，而游戏格子都较鲜艳）。
     后者不可省略：图标颜色若恰好均匀，5 个采样块会"一致地错"，共识度仍是 1.0。
   - 回填：颜色区域必须四连通，所以该格的颜色必然出现在它的四邻格中，
     候选色只需从邻格取；再要求填入后不把某种颜色拆成两块，
     并优先选"填入后该颜色区域大小更接近平均 n 格"的候选。
   - 局限：若某种颜色在整张图上只有 1 格、且正好被遮挡，该颜色信息不可恢复（信息论上缺失）。
4. **CIELAB 聚类**：把颜色转到感知均匀的 CIELAB 空间，用 ΔE76 距离聚类
   （浅粉/浅橙这类 RGB 上很接近的颜色在 Lab 里更好分）。容差不再固定：
   从 30 到 1.5 逐级尝试，簇数多于/少于 n 时自动合并最相近的簇、拆分最分散的簇。
5. **自愈回路**：每个容差产生一种颜色划分，去重后按轮廓系数（silhouette）评分排序。
   求解时依次尝试：某种划分不连通、或解不出，就自动换下一种，直到拿到答案。
   因此单个容差选得不合适不会导致整体失败。
6. **求解**：位掩码 + 前向检查 + 回溯（最小剩余值排序），统计解的个数（上限 50），
   输出第一个；输出前用独立的校验函数复核三条规则。
   - **前向检查**：每放一只猫，立刻把"这一格 + 它的 8 邻居 + 整行 + 整列"从其它颜色的
     候选集中剔除，一旦某个颜色候选为空就立即回退，比每层临时统计更早剪枝。

## 关键实现细节

1. **规则理解**：第三条规则是八邻——任何两只猫不能相邻，包括对角线。
   早期版本只禁上下左右，导致同一关卡出现多个"合法解"。
2. **冲突计算**：猫只占它所在颜色区域里的**一格**，放猫时的冲突只应禁止
   **该格子**的邻居。早期版本按"整个颜色区域所有格子的邻居并集"来禁，
   属于过度约束，会把本来有解的关卡判成无解。
3. **划分评分**：早期用"簇间最小距离 / 簇内最大离散度"给划分打分，只看两个全局极值，
   完全不同的划分会算出同一个分数，于是"修复过"的错误划分靠先后顺序赢了平局。
   改用轮廓系数后，正确划分稳定胜出。
4. **定位退化**：只靠"饱和度缝隙"定位时，一张被缩小到 567px 的截图会让缝隙糊平，
   棋盘被误判成 2×2（把整块棋盘当成 4 个大格子），于是必然报"无解"。
   现在 A 失败会自动退回周期法；实测该图两轴都测出格子边长 42px，
   499 ÷ 42 ≈ 11.88 → n=12，采样共识度 0.99，一次命中唯一解。
5. **周期倍数**：自相关会把 2 倍周期也算成强相关（n 会被估成一半）。
   取"接近最强相关里最小的周期"后稳定正确。
6. **棋盘外框**：只取"最长的一段连续超阈值区间"会被个别偏低的像素行截断
   （某行刚好是浅色格子时彩色像素数掉到阈值以下，外框只剩 1/3）；
   直接取 min/max 又会把界面元素并进来。现在以最长段为中心，
   把缝隙不超过段长 10% 的相邻区间并进来，并改用最大彩色连通块作主选外框。
   这里踩过两个坑：扩展时必须**双向分别扫描**——先前的单向遍历里，
   前面被拒的区间不会在边界缩小后重新吸回，导致外框从棋盘中部才开始；
   向上扩展的比较方向还写反过一次，等于无条件吞并右侧/下方的所有区间。
7. **浅色格子的连锁反应**：缝隙本身只有 2~3 行像素低于阈值，但单向遍历时
   一次拒绝就会让外框整体偏移一整块，进而让 n 估成 4、8 之类的怪值。
   改成两个方向都"够近就吸收、一旦够不着就停"后，18 个用例全部稳定。
8. **预亮猫的遮挡**：游戏默认会提示一只猫的位置，猫脸图标把那格盖得严严实实。
   实测该格 5 个采样块全落在图标上（`8a807a` / `343232` / `322c2a` / `e1dad8` / `e0d8d2`，
   饱和度仅 3~15），真实底色 `aed994` 一个像素都没采到，于是它被聚成独立一簇，
   "颜色 1 被划成了 2 块"，17 档容差全部收敛到同一个错误划分，自愈回路无处可退。
   关键数据：被遮挡格的最大饱和度只有 15，而其余格子最低也有 69——
   这就是"低饱和度"判据的依据；只要把它摘出聚类，任何容差都能稳定聚出正确的 6 种颜色。
   遮挡压力测试（把不同格子逐一涂成灰白图标）从 2/6 通过提升到 5/6，
   唯一失败的是一次性遮住"全图只有 1 格"的稀有颜色，属信息论上不可恢复。

修正后，开发期测试过的 15 张示例（8×8 ~ 16×16、含 2 张被缩小到 560px 左右的截图、
1 张带预亮猫遮挡的 6×6）全部一次命中并解出唯一解；
另外把 5 张原图压到 560px 做压力测试，也都一次解出、且坐标与原图完全一致。
仓库中只保留了 3 张有代表性的截图（见上文"命令行版"表格）。
